# Walk-Forward Evaluation Harness V1

Deterministic, chronological walk-forward evaluation for registered strategies.
**Evaluation only** — no parameter optimization, RL training, auto-promotion, or trading.

## Architecture

```
Historical bars
  → SplitSpec (date / percentage / bar-count)
  → generate_windows (rolling | expanding | fixed)
  → per period (TRAIN / VALIDATION / OOS):
        warm-up bars + ScoreWindowGateStrategy
        → BacktestEngine (fresh capital, no position carry-over)
        → filter scored trades (entry inside period)
        → StrategyEvaluationService (regimes, warnings)
  → Role aggregates + descriptive robustness
  → MarketMemoryService.persist_walk_forward (optional)
```

## Rolling vs expanding

| Mode | Train window | Val / OOS |
|---|---|---|
| `rolling` | Fixed length; start advances by `step_bars` | Slide forward with train |
| `expanding` | Starts at series begin; end grows by `step_bars` | Slide forward after train end |
| `fixed` | Single date- or percentage-based split | One window |

Parameters are **fixed across all windows** in V1.

## Data split rules

- Scored periods are half-open `[score_start, score_end)` and contiguous/non-overlapping.
- Warm-up bars precede `score_start` for indicator history only.
- `ScoreWindowGateStrategy` returns `NO_ACTION` outside the scored window so warm-up cannot open positions.
- Minimum bar counts are enforced; insufficient history raises `InsufficientHistoryError`.

## Leakage protections

- BacktestEngine lookahead-safe bar views (existing).
- Train/validation bar slices must not include OOS timestamps.
- Forward-looking label horizons (`label_horizon_bars`) require purge/embargo gap or the run is rejected (`DataLeakageError`).
- Results are never labeled OOS if parameters were selected on that OOS period — V1 does not select parameters at all.

## Backtest boundary assumptions

- Independent windows: starting capital reset; `position_carryover=False`.
- Signal at bar close / fill at next open (existing execution model).
- Only trades with `entry_time` in the scored window contribute to period metrics.
- Pending unfilled orders at period end are not scored as trades.

## Performance aggregation

- Per-period reports for TRAIN, VALIDATION, OUT_OF_SAMPLE.
- Aggregates use **compounded** window returns and **trade-weighted** win rate.
- Overlapping scored windows are not generated by the splitter; aggregates warn if indices collide.

## Market Memory integration

- Event type: `walk_forward_evaluation_summary`
- Source: `walk_forward_evaluation_v1`
- Evidence id: `harness_id` (stable; independent of wall-clock time)
- Stores compact `period_summaries`, aggregates, robustness, hashes — not OHLCV or equity curves
- Idempotent; immutable (conflict on payload change)

## Evidence limitations

Warnings may include missing/small OOS samples, zero-cost assumptions, unreliable regime buckets, missing warm-up, and forward-label rejection. Descriptive robustness does **not** invent confidence levels. A green test suite is not profitability evidence.

## Strategy compatibility

Supported fixed-parameter evaluation:

- SMA crossover
- RSI/MACD trend
- Qlib-inspired factor signal (`qlib_factor_signal`) with research provenance

FinRL-X baseline (`finrlx_baseline_signal`): only with `allow_finrlx_baseline=True`; never presented as trained RL.

Unsupported strategies raise `UnsupportedStrategyError`.

## Future parameter optimization

Out of scope for V1. A future optimizer must:

1. Select parameters using TRAIN/VALIDATION only
2. Freeze parameters before OOS
3. Never tune on OOS
4. Persist selection provenance separately from OOS evidence

## Database migration

**NO** — reuses `market_memory_events`.
